## Major (design / statistics; fix before Stage 1 outputs are looked at; record as dated Amendments, not edits)
1. R3 criterion "queries-per-catch <= 20 at recall 0.5" is vacuous or incoherent on its stated dataset. Random-ask on E-cap4 polarity costs about 1/0.114 = 8.8 queries per catch, so a policy at 20 is worse than random (the plan itself says ~9). The bar is only meaningful on E-human (random ~37). State the bar per dataset (e.g. strictly below random-ask's QPC with paired CI).
2. Stage stats inherit enrichment: E-cap4 and E-human are 300 enriched + 300 random with HT weights, but AUROC (R2), ECE/Brier, probe AUROC (R4) are not stated to be HT-weighted. Unweighted AUROC on an enriched sample answers a different question than the population one. Specify weighted vs unweighted for each, and report both.
3. Power. E-cap4 has about 68 positives (600 x 11.4%) and E-human polarity about 2.7% of 1,800 sets, with 3 sets per message highly correlated (cluster by message, as planned, but effective n is 600, ~16 positives in E-human). H3/R2 needs lower CI > 0.55 in >= 3 of 5 models on the SAME items; models are not independent evidence (shared items, shared labels), so "3 of 5 models" is closer to one replicate than three. Holm across models is not the right fix; state a pooled test with model as a random effect or report as one dataset. 5-fold CV unigram LR with ~68 positives is a weak and noisy lexical baseline; "beats lexical by 0.03" is easy to pass for a poor baseline. Add stronger lexical/semantic baselines (sentence-embedding LR, a small fine-tuned classifier, content-word-count + verb-presence, and the T2 detector features) and an "always-same-score" and keyword-count control.
3b. Stage 3 adds 2,400 cap4 messages, but the labelled source negation comes from the detector; fine for scale only if Part 21 validates detector error on cap4 (cap4 compression changes which negations are lost; detector FN rate there is unknown).
4. Circularity/shared-labeler risk: output polarity labels (sampled generations) and source polarity labels both come from src/labels.py. A detector blind spot (e.g. "can't", "without", "never mind", "refuse", "stop") is correlated across the model-share and the target, which biases both the ratio r and any AUROC in the same direction. The 300-output judge subset checks outputs only; the source side relies on Part 21 (not yet back). R1's classification should not be headlined before Part 21.
5. R1 band is loose and ignores target uncertainty. "Calibrated" = ratio in [0.5, 2], i.e. 1.35% to 5.4%, vs a posterior whose own CI is [1.8, 3.7]. A model at 1.4% and a model at 5.3% both pass, though they differ 4x. The target CI is also not propagated (posterior and model share are estimated on the same messages). Test equivalence formally (TOST/ratio CI contained in [0.5,2]) with the target uncertainty included, rather than "CI not entirely below 1.35%", which is a one-sided non-rejection and passes for very wide CIs. With ~2.7% positives and ~1,800 sets, a CI can easily span both "overconfident" and "calibrated" - then neither label applies; add an explicit "inconclusive" class (currently the headline rule can classify by default).
6. Sampled share vs posterior is not the same estimand as calibration. P(model emits negated | bare keywords) averaged over inputs equals the posterior only if the model and humans see the same conditioning. The model sees a prompt with an instruction to write "the" sentence; outputs also differ in surface (hedges, "can't", "don't know"). Calibration in aggregate (the base rate) says nothing about per-input reliability; the plan has Metric 2 for that, but H1's "decoding problem" headline from aggregate share alone would overclaim: a model emitting 2.7% negations at random is "calibrated" by R1 and useless by R2. Headline must be the conjunction.
7. Temperature=1 untruncated sampling of Q4 instruct chat models is not the deployed behaviour and tail mass of instruct models at T=1 is known to include degenerate outputs; the share of "negated" outputs may be inflated by incoherent or off-task samples that trip the detector. Report share among well-formed outputs, and the finish=length rate (96 max_tokens, the pilot counts it).
8. Pair-scoring arm (E-pairs, sum logprob of full source sentences, normalised over {A,B}) is confounded: A and B differ in length and wording ("take" vs "do not take"), so a summed-logprob softmax mostly measures length/word frequency, not polarity belief. Need length-normalised or divergent-span-only scoring, and a placebo contrast (same-length non-polarity edit). The plan also calls candidate sentences "source" text written by people, whose fluency under the model differs from model-style output. Given the design is 50/50, "0.5 = indifferent" interpretation is not licensed.
9. The pilot's mechanics pass/fail rule is not numeric ("verified on a hand-checked toy"). The script computes a TV distance and a noise approximation but no declared threshold; write it down (e.g. TV <= 1.5x expected noise) before the run. The `has_prompt_logprobs` expression in the script contains `... and False` and is dead logic, so the endpoint probe would report only the substring "prompt_logprobs" in the response; the stated pass/fail for prompt logprobs is effectively unobserved except through forced decoding.
10. Forced-decoding scorer: candidates tokenized separately from the prompt (no join-token check; only one greedy example is compared to generation logprobs) and top-1000 probabilities can omit the target token (counted as missing, silently turning the pair row to None). Missing is recorded but there is no stop rule. Also a single consistency example is too thin to call the scorer validated.
11. Baselines against the AAC-facing comparison are not yet specified enough: the plan lists current-study interventions (chip, plain word, G1) but G1 is run only on E-pairs while policies are scored on E-cap4/E-human; the headline "improvement in AAC terms" will compare against always-commit and random-ask only on that data. Say plainly that guard G1 is not compared on the same items, or run its classifier component on them. Also add the strongest cheap baseline: a lexical/keyword-rule asker ("ask when keywords contain a verb with typical negation, or length <= k") and a threshold on greedy token entropy / top-1 prob (free, single-pass), which is the obvious deployable competitor to K=16 sampling (16x cost).
