# knows_not_says, round 3 (last round): results

Working title: "Which reading does the model drop? Sampling-distribution calibration for AAC message expansion" (renamed from "Knows but does not say" because of the closeness to arXiv 2605.25284 "Knowing but Not Showing"; the id knows_not_says is only a file name).
Status of everything below: PROVISIONAL. Labels are from a rule-based detector (src/layer0.py) on both the typed sentences and the model outputs; it was checked only against a machine reference (section 3), not against humans. Part 21 (human check of source labels, `annotation/returns_source_check`) still has 0 returned files. All "asking" gains are simulated and assume that asking resolves the cue to the source label. Pre-registration: PLAN.md amendments A1-A25 were written before the single full analysis run (A24 documents one dry run on qwen at B = 200 used only for crash detection; I did see its table, and no rule changed after it).

## 0. Scope actually covered (stated plainly)
Two models ran: **qwen2.5-7b and llama3.1-8b** (Q4_K_M, llama.cpp b12019, prompt P0n, K = 16 samples at T = 1 with explicitly untruncated sampling, plus one greedy run with top-20 logprobs, 0 request errors, 29,461 requests per model). NOT run: qwen2.5-14b, mistral-nemo-12b, gemma3-4b, the legend arm P0, the temperature curve, the GPT/Gemini sampling arm, verbalised-confidence baseline, Stage 3 (steering/decoders at scale) and Stage 4 (probes). Two models on the same items are consistency, not independent replication; the inferential unit is the message (10,000 message resamples, stratified by sample type, identical resample for both models), and the model-pooled row uses that same resample. Data: E-cap4 = 540 messages, one cap-4 keyword set each (107 source-negated no-cue units, confirmatory-eligible); E-human = 1,367 no-cue units from 3 human keyword sets per message (68 source-negated; EXPLORATORY). The planned "about 68 / about 16" positives were under-estimates; the actual counts are 107 and 68 (the human subset is still labelled exploratory by the declared rule).

## 1. Stage 0 mechanics (A18, honest account of A10)
- Logprob coverage 7,550/7,550 tokens (100%). Explicit top_k = 0, top_p = 1, min_p = 0 reproduces server probabilities (20 prompts x 200 draws, mean |dev| 0.0055, max 0.028); the server defaults (top_k 40, top_p 0.95, min_p 0.05) produced 0 tail draws against 14.1 expected, so default decoding hides the tail and the untruncated sampler is mandatory.
- **A1(c) as written FAILED**: forced-decoding logprobs matched generation logprobs within 0.05 nats on 34/50 sequences (68%) against the 95% required. A10 is a post-failure replacement rule (written before Stage 1 outcomes, after seeing the failure), not a pass.
- Repeat baseline of the same server against itself, both ways: 36/46 = 78% conditional on identical text; 36/50 = 72% over all 50 sequences; without prompt cache 29/46 = 63% conditional, 29/50 = 58% over all. Forced decoding (68%) is 4 points below the all-50 repeat rate, exactly 10 points below the conditional rate (the A10 margin, met at the boundary) and above the no-cache rate. It passes only the most lenient reading, so the pair-scoring arm is noise-limited (0.1-0.4 nats at single tokens; about 8% of greedy repeats change text).
- /embedding returned 501 (no --embeddings); dropped. Throughput 19-21 req/s, 0.4 h per model.

## 2. Headline in one paragraph
On bare keywords the two models almost never produce the negation that the typed sentence had and the keywords dropped, and their own sampling distribution does not flag the inputs where this happens. On E-cap4, 10.8% of no-cue units (source posterior, detector-relative) had a negated source; greedy outputs are negated in 0.39% (qwen) and 0.98% (llama), sampled outputs in 0.49% and 1.57% (R1 ratio 0.05 and 0.15; "overconfident"). The sampled share is exactly 0 for 97% (qwen) and 87% (llama) of units, so the per-input score is mostly ties, and its AUROC is 0.53 (qwen) and 0.59 (llama), below a keyword-only logistic baseline (0.64). The pre-registered R2 ("the model knows which inputs") fails; the data say the tested models are overconfident and uninformative about this cue. The AAC-relevant gain does not come from the model's uncertainty; it comes from asking, and a model-free lexical ask does as well as the semantic-entropy-style ask. Oracle-triggered chips and plain words are the upper bound.

The A/B/C story needs R1 and R2 together: R1 overconfident (qwen both sets), R2 negative, so "miscalibrated and uninformative".
**Detector validity (A12/A19, machine reference, T7).** Reference = judge J1+J2 (gpt-6.1-sol; they agreed on 827/834 sentences, kappa 0.977) plus a blind arbiter on 7 disputes (I decided from the sentence text only: "I don't know"-type uncertainty wording coded unclear/mixed per the codebook, so counted as NOT negated). Predictive values: model outputs qwen PPV 29/34 = 0.85 [0.70, 0.94], llama 73/100 = 0.73 [0.64, 0.81]; NPV 300/300 = 1.00 [0.987, 1.000] for both; typed sources PPV 37/50 = 0.74 [0.60, 0.84], NPV 50/50 = 1.00 [0.93, 1.00]. So the detector's false positives (mostly "I don't know" and contrastive "not") are the weakness; no false negative was found among 650 detector-negative sentences. Derived specificity is 0.97-1.00, sensitivity 1.00 (derived, labelled so). The corrected ratios (predictive-value correction, Beta posteriors inside the bootstrap) leave every class unchanged. R1 is therefore "detector-relative, validated against a machine reference only"; if uncertainty wording were counted as negated, PPV would rise toward 1 and the source posterior would rise too, so the overconfidence conclusion would not weaken. Human confirmation: `ANNOTATION_REQUEST.md` (534 items, not sent).
Politeness and speech act (T1b) are descriptive and unvalidated: qwen samples politeness at 2.1% vs 3.7% source (E-cap4, inconclusive), llama 5.9% vs 3.7% (ratio 1.58, inconclusive); speech act (non-statement) is overconfident in both models on both sets (ratios 0.17-0.42).
Reliability (T5): ECE 0.10 (E-cap4) and 0.03 (E-human), but these are no better than a constant base-rate predictor (Brier 0.104 vs 0.096 on E-cap4 for both models).

Reading: the semantic-entropy-style ask helps only for llama and then only as much as a keyword classifier that uses no model at all; in qwen the model's own sampling spread adds nothing, and greedy first-token entropy never beats random-ask in either model.
- **Closest implementable prior methods.** (a) Semantic-entropy-style disagreement/sampled-share ask (Kuhn, Gal, Farquhar, ICLR 2023 idea, implemented as the share of 16 samples with a negated reading; a scalar proxy, not their clustering): mixed as above. (b) Contextual calibration (Zhao et al., ICML 2021, "Calibrate Before Use"; content-free input "Keywords: N/A"): degenerate or non-beating random-ask in both models (llama's content-free input itself yields a negated reading in 6/16 samples, which distorts the shift). (c) Platt-calibrated cost-optimal ask, refit for each w_spur and tap cost c: at c = 0.03 the Platt rule asks 236 (qwen) and 174 (llama) per 1,000 on E-human and almost everything on E-cap4 (998-1,000 per 1,000) because the base rate (10%) exceeds the tap price (contextual calibration: 312 / 14 per 1,000 on E-human, 997 / 31 on E-cap4); at c = 0.1 it asks fewer than 20 per 1,000 and does not beat random-ask (caught-minus-random -0.1 to +0.1), so cost-optimal rules collapse to either "ask all" or "ask none". Not implemented: SpeakFaster-style fine-tuned keyword expansion with candidate ranking (Cai et al., arXiv 2312.01532 / Nat. Commun. 2024; snippet-level read only), and any probe-based estimator (Stage 4 gated off).
- **Where the method does not help.** qwen sampled-share ask (no gain over random-ask), greedy first-token entropy (both models), contextual calibration and Platt at realistic tap costs, G1 (acts only on supplied cues; on bare keywords it raised 0 polarity flags: its only flags were 388 and 431 politeness additions on 2,160 outputs, which is a different channel), E-human for qwen (23.8 reversals per 1,000, no policy except the lexical 25/100 beats random). On E-human llama sampled-share @ 10/100 gives 15.6 [8.8, 23.8] vs 23.3 for always-commit at 99.9 taps (exploratory).
- **Honest scale of the problem in AAC terms.** Always-commit silently reverses 104 per 1,000 E-cap4 messages (about 1 in 10 messages whose cap-4 keywords lost a negation) and about 23 per 1,000 E-human messages, essentially all of the source-negated no-cue units (recall of the negation by greedy decoding is about 3% on E-cap4). That is the price of the status quo for this cue on bare keywords; the NEG weight from the SLP ratings is 5.0/5, so each is a full-weight error. Realistic model-side asking can remove 20-40% of them at 100-250 extra taps per 1,000; only a user-supplied cue (chip or plain word, oracle-triggered here, so a best case that ignores the cost of knowing when to add it) removes about 99%.

## 6. Pair scoring (PROVISIONAL, noise-limited; table T8)
Given bare keywords, the forced-decoding log-odds of the affirmative over the negated variant (164 hw1 + W-C polarity pairs): affirmative preferred for 94% (qwen) and 91% (llama) of pairs under the full-sum scorer, 98% and 97% under the divergent-span sum, but only 68% and 51% under the length-normalised scorer, where 29-37% of pairs exceed the 95th percentile of placebo |log-odds| (contraction toggle and final-period placebos). The scorer therefore matters: the span-sum preference is partly a length/wording effect (the contraction-toggle placebo alone has median |log-odds| 3.7 nats in qwen). Top-1000 imputation (A18): in qwen 49 of 164 pairs carry an imputed token (13 aff only, 10 neg only, 26 both; llama only 8 pairs); the clean-subset share (qwen 0.94 full-sum; n = 115; llama n = 156) matches the all-pair share, and a conservative bound that flips every sign-unsafe pair still leaves 0.87 (qwen) and 0.89 (llama) for full-sum. Correlation of the span-sum with the sampled negated share on the same bare inputs is -0.25 / -0.28 (mean sampled negated share 1.9-2.2%). This arm supports "the affirmative reading is far more probable", not any claim about indifference.

## 7. What can and cannot be claimed
Can (provisional): (i) on bare keywords, greedy decoding silently drops the negation in about 10% of E-cap4 units and about 2% of E-human units, and the sampled share is about 7-20 times too low relative to the human omission posterior on E-cap4 (and for qwen on E-human; llama on E-human is inconclusive); (ii) the per-input sampled share is a weak, mostly-tied signal (AUROC 0.53-0.59) that a model-free keyword classifier beats or matches; (iii) in a simulation that assumes asking resolves the cue, an oracle-triggered cue brings reversals from about 104 to about 1 per 1,000 for 108 taps per 1,000 messages, while model-side triggering recovers only about a fifth to two fifths at 100-250 taps. Cannot: any claim about real users, acceptability, or real tap costs; any validated claim about politeness or speech act; "k of 5 models"; anything about probes or steering (not run).
Null/negative results kept in: R2 fails; qwen's sampled-share ask does not beat random; first-token entropy never beats random; contextual calibration and Platt do not beat random at c = 0.1; G1 not applicable; E-human llama R1 inconclusive; the posterior and PPV are detector-relative.
Stage 4 gate: H3 AUROC >= 0.60 in >= 2 models is NOT met (0.53 and 0.59), so probes and steering were not run; by the pre-registered stop rule (R1 overconfident, R2 negative, R3 not discriminating against the model-free baseline) Stages 3-4 are cancelled.

## 8. Problems and caveats
- The detector is the weak link (PPV 0.73-0.85); the reference is a machine judge plus one blind arbiter (me), and the uncertainty-wording convention matters. Humans have not checked anything (request written, 534 items, not sent; Part 21 still empty).
- Before the plan fixed the draw I saw only detector-label counts while drawing the validity sample: qwen has just 34 units with any detector-negated sample, which forced the A19c redraw rule (documented). The dry run (A24) showed qwen R1/R2 shape before the full run; nothing changed after it.
- Two models, same items: not replication. The lexical baseline is trained on the same source labels (5-fold message-grouped cross-fitting), so it is an upper-ish model-free reference that needs labelled data in deployment.
- Entropy baselines use the top-20 truncated approximation; `greedy` repeats are not run-to-run deterministic (about 8% text changes); the llama content-free input produces negation, which affects only the contextual-calibration arm.
- Platt/contextual "recovers R3 = YES" flags on E-cap4 for ask-almost-everything rows are artefacts (asking 998/1000 units trivially exceeds matched random-ask by 0.2 per 1,000); read the taps column.
- Literature was checked at snippet level only (semantic uncertainty, Calibrate Before Use, arXiv 2605.25284, SpeakFaster/Cai et al.); nothing was read in full text and nothing unverified is cited.
