# A4 CPU hardening: analysis plan (written 2026-11-18 BEFORE any script in this folder was run)

Status: not committed. Frozen estimates (analysis/listener_human, expert_package SLP report, annotation/returns_* scorers) stay the headline everywhere. Everything here is a sensitivity or an audit; nothing replaces a frozen primary. No new human data, no GPU, no model calls. Runs on CPU in `. .venv/bin/activate`, statsmodels installed for this purpose (uv pip install statsmodels, 0.15.0). Code: `analysis/hardening/run_hardening.py` (one script, seeded 20261117).

## 1. Listener study, crossed listener x item model (sensitivity)
Data: exactly the rows the frozen scorer uses (src/score_listener_study.py qc -> decode -> exclusions -> expand; 20 listeners, 846 unit judgments, expanded to judgments by condition). No exclusions occur; none are added.
Outcomes: success (Q1 = intended reading), received reversal (Q1 = opposite reading), opposite action (Q2 = opposite action; rows with no Q2 excluded), and unclear as context.
Contrasts: chip1 - bare (all 120 items), G1 - bare (inert by construction; reported only), nlcue - chip1 (hw1 items). Bare - reference is not refit.
Models, all reported side by side, none chosen after the fact:
 M1 logistic GLMM, fixed effect of condition, crossed random intercepts item and listener, statsmodels BinomialBayesMixedGLM fit by variational Bayes (the only crossed-effects binomial GLMM in statsmodels; posterior means; fixed-effect and variance-component draws give the marginal (population-averaged) probability per condition and the contrast in pp; 95% central interval of 20,000 draws). VB intervals are known to be too narrow; M1 is read as a point/direction check, not as the interval.
 M2 linear probability model, condition fixed effect, two-way cluster-robust covariance (items x listeners, Cameron-Gelbach-Miller), Wald 95% interval.
 M3 paired version: M2 with item fixed effects, cluster-robust by listener (within-item contrast).
 The frozen two-way cluster bootstrap (10,000 resamples) is shown beside them. For rare events (reversal, 6/240 bare vs 1/240 chip judgments) M1-M3 are expected to be poorly behaved; they are reported and labelled so.
Also variance components (item, listener) from M1 and a count of listener x item cells.
Decision: the frozen conclusion (chip raises success; opposite action falls; reversal difference not confirmed) is "unchanged" if the sign agrees in M1-M3 and the M2/M3 interval for success and opposite action excludes 0 and the reversal interval includes 0 (or is not narrower than the frozen one in a direction that would confirm it). Otherwise "changes" and is reported as such.

## 2. Leakage audit
(a) Direct: key listener ids vs data/items/hw.jsonl and hw2.jsonl writer_id, and vs the three checkers in analysis/hw_checks/items.csv and analysis/hw2_checks/items.csv for the 120 drawn families; zero overlap is the rule (PLAN section 6 of analysis/listener).
(b) Within-study exposure: listeners who judged more than one judge unit of the same item (and whether the reference unit and a model-made unit of an item went to the same listener).
(c) Cross-stage exposure: for every listener, whether the text of any of the 120 families' two source sentences, or the stimulus output sentence, occurs in that listener's own earlier packet files (annotation_package/stage*/<ID>_*.json, other than the Part 28 file) or in the shared package files; and, from the item tables, Part 18 (writer-intent) own-pair outputs and Part 26/27 own-pair sets. Reported as counts by stage and role; a listener-item pair with prior exposure is a "contaminated cell". Sensitivity: refit M2/M3 and rerun the frozen point estimates dropping contaminated cells.

## 3. SLP weight sensitivity
Every SLP-weighted number in the two papers: CALE-AI slp_wc_base/guard, slp_hw_base/chip/word (weighted failure rate; src/score_slp_panel.py weights_from/weighted_rate on expert_package/judge_failure_counts.csv) and listener ls_slp_bare/chip (slp-weighted reversal per 1,000). SE4All reports no weighted rate (only the severity 5/5 and acceptance counts; verified by grep). Recomputed under: frozen mean weights; each rater alone (leave-one-SLP-out, n = 2, so each is also the only remaining rater); uniform weights 1.0 (= unweighted any-failure rate); uniform 0.8; rank-based weights. Reports whether the within-population ordering and the relative reduction survive each scheme. Listener SLP-weighted reversal: per-rater dimension weights (polarity=NEG, speech_act=ACT, agent=AGT, time_quantity=TIM), cell values and chip - bare contrast with the frozen two-way bootstrap (B = 2,000 here).

## 4. Power / MDE
Primary human endpoints: Part 17 (usable, repaired - control, 60 v 60 items, Newcombe, margin -10 pp), Part 18 (writer-intent match, chip - bare, 20 writer clusters, 97 v 98 items), Part 28 (success chip - bare; also opposite action and reversal; paired items x crossed listeners), Stage 6 (Parts 26/27 H-cov primary contrasts, 100 items, writer clusters). MDE at 80% power, two-sided alpha 0.05, defined as 2.80 x the achieved standard error of the frozen design (SE recovered from the frozen CI half-width/1.96, or recomputed for Part 17 and 18 from the design with the observed design effect), plus for Part 17 the power of the frozen non-inferiority rule at a true difference of 0 and -5 pp, and the sample size per arm for 80% power at -10 pp. Never "observed power"; this is the sensitivity of the design, stated as what the study could detect.

## 5. Estimand table (<= 10 rows) for CALE-AI
Columns: claim, estimand, population, design, estimate, status in {measured, human-judged, machine, projection}. Rows taken from the frozen estimates. The chain "cue supply (q-hat = 0.736, speech act only) -> machine restoration (same-items speech act: 29.9% bare, 75.6% chip) -> listener success (chip - bare, frozen)" is shown with the AAC-user link as explicit unmeasured factor s in [0, 1] (probability that a person who uses AAC supplies the needed cue and picks the restored draft). Projection = arithmetic only: gain_pp(s) = s x gain(cue-in-hand), with bounds s = 0 (worst: 0 pp) and s = 1 (best: the cue-in-hand gain), plus the same with the measured interval ends; labelled "projection, not a finding". Listener success already embeds machine restoration for the chip arm (the listeners judged the stored chip outputs), so q is applied once to the cue-in-hand gain, not multiplied with the restoration share again.
Outputs: report.md, summary.json, estimand_table.csv, estimand_table.tex (data rows only; macros are made by the paper's make_macros.py, not here).
